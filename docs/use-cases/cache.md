# 缓存

把热点数据放在 Redis 里，读请求命中就不用再走数据库。命中率从 90% 提到 99%，回源查询量降到原来的十分之一，这是缓存最直接的收益。代价是多了一份要维护的数据：缓存和数据库不一致、键过期集中、不存在的数据反复打穿缓存，三个问题都要在设计时处理。

## 这一页的三个问题

- 缓存穿透是请求的数据两边都不存在，每次都回源；对空结果也写一个短 TTL 的键，或者用布隆过滤器先挡一层。
- 缓存击穿是单个热点键过期瞬间涌进来的并发回源；用 `SET key value NX EX 5` 的互斥锁只放一个请求进去重建，其余请求等它写完。
- 缓存雪崩是大量键同时过期；在基础 TTL 上叠加随机抖动，把过期时间错开。
