# 任务队列

耗时任务（发邮件、图片转码、报表生成）不应卡在用户请求里：把任务写入队列立即返回，后台 Worker 取出执行。Redis 的三种结构都能搭队列，按投递语义选。

## 选型要点

- List 队列用 `LPUSH` + `BRPOP`，实现最简单，单条取出即丢，没有确认与重试；
-  Streams 消费者组实现「一条条目只投递给组内一个消费者」的语义：读取后进入待确认列表，处理完 `XACK` 才移除，失败可转交重试，适合不能丢的任务；
- 需要延迟执行的任务（30 分钟后超时取消）用 ZSET 实现：分数存执行时间戳，轮询取出到期任务，比 List 的忙轮询省资源。

## 设计要点

- 明确投递语义：至少一次还是至多一次，Streams 确认语义对应至少一次；
- Worker 崩溃会留下未确认条目，需要监控待确认列表并配置转交阈值；
- 记录任务处理耗时与失败次数，超过上限进入死信，避免毒任务无限重试。
