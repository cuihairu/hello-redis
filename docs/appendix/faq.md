# 常见问题解答

## 持久化

**Q：RDB 和 AOF 怎么选？**
RDB 是时间点快照，恢复快、文件小，但两次快照之间的数据会丢；AOF 记录写命令，`appendfsync everysec` 最多丢约 1 秒数据。多数场景选择"两者都开"：AOF 保数据、RDB 用于快速恢复与备份。详见[RDB快照](../advanced/rdb-snapshot.md)与[AOF日志](../advanced/aof-log.md)。

**Q：Redis 重启后数据丢了？**
先确认是否开启了持久化（`INFO persistence` 中 `rdb_last_save_status`、`aof_enabled`），以及是否设置了 `dir` 指向持久化文件目录。只缓存数据的场景允许丢失，此时不开启持久化是正常的。

## 内存与淘汰

**Q：内存满了会怎样？**
达到 `maxmemory` 后按 `maxmemory-policy` 淘汰键。缓存场景常用 `allkeys-lru`；不允许丢数据时用 `noeviction`（写命令返回 OOM 错误），此时应尽快扩容。

**Q：键很多但内存不够，怎么排查？**
用 `redis-cli --bigkeys`、`--memkeys` 或 `MEMORY USAGE` 找大键；检查是否有大集合、未设 TTL 的缓存键、不断增长的列表。也可把 RDB 导出后用 `rdb_tools` 离线统计。

**Q：键设置了 TTL，会自动删除吗？**
会。过期键由惰性删除（访问时发现已过期即删）与主动删除（`activeExpireCycle` 周期抽样）共同清理，内存及时回收。但注意过期键可能被 `RENAME` 覆盖等边界情况。

## 缓存

**Q：缓存穿透、击穿、雪崩的区别？**
穿透是查不存在的数据绕过缓存；击穿是单个热点键过期瞬间大量请求回源；雪崩是大量键同时过期导致数据库被压垮。对策分别为空值缓存/布隆过滤器、互斥锁重建或不过期、TTL 加随机抖动。详见[缓存](../use-cases/caching.md)。

**Q：先更新数据库还是先删缓存？**
推荐"先更新数据库，再删除缓存"（Cache-Aside）。删除失败会读到旧值，可用重试队列或短 TTL 兜底。

## 高可用与集群

**Q：哨兵和集群的区别？**
哨兵解决高可用（自动故障转移、配置提供），数据仍是单点全量；集群同时解决水平扩展（16384 个槽分片）与高可用（主从 + 故障转移）。

**Q：Redis 集群最多多少个节点？**
理论上限受总槽位与主节点数限制，官方建议主节点不超过 1000 个，生产常见规模几十个主节点。

**Q：执行 `redis-cli -c cluster reshard` 报错？**
写法不对：`cluster reshard` 不是 `CLUSTER` 命令的子命令，`-c` 只是让 `redis-cli` 跟随 `MOVED` 重定向。槽迁移应使用集群管理工具：`redis-cli --cluster reshard <节点地址>:<端口>`。

## 命令与性能

**Q：为什么不能用 `KEYS`？**
`KEYS` 是 O(N) 且中间不释放 CPU，键多时会阻塞所有请求。改用 `SCAN` 渐进遍历，或用集合/哈希维护业务索引。

**Q：`MULTI/EXEC` 是原子的吗？**
事务中的命令会被排队并在 `EXEC` 时连续执行，期间其他客户端的命令不会插入——是原子的；但事务不支持回滚，某条命令运行时出错（如对字符串执行 `INCR`）不会中断后续命令。

**Q：`INCR` 会重复吗？**
不会。Redis 单线程执行，`INCR` 是原子自增，多实例同时调用也返回不重复的值，因此可直接做发号器。

**Q：大键（big key）如何定义与处理？**
一般把 String 超过 10 KB、集合元素超过 5000 个视为大键。它们会导致命令变慢、内存不均、删除阻塞。处理方式：拆分（分段、分片）、改用压缩存储、删除用 `UNLINK` 异步执行。

## 客户端

**Q：连接池怎么配？**
连接数并非越大越好，Redis 的吞吐瓶颈常在单实例命令处理。经验值：小型应用 8~32 个连接；需要大量管道时减少连接数、增大管道深度。

**Q：客户端收到 `MOVED/ASK` 错误？**
说明请求的键不在当前节点，客户端应使用集群模式连接（如 go-redis 的 `NewClusterClient`、node-redis 的 cluster 支持），或由代理转发。

**Q：`error READONLY` 是什么原因？**
连接的主节点发生了故障转移，原主节点变为从节点并拒绝写入。客户端应根据哨兵通知或集群重定向机制重新获取主节点地址。
