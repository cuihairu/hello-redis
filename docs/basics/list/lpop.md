# LPOP

`LPOP` 移除并返回列表头部的元素，是出队、弹栈操作的标准命令。时间复杂度为 O(1)。

## 语法

```plaintext
LPOP key [count]
```

## 参数说明

- `key`: 列表的键名。
- `count`: 可选，一次弹出多个元素（Redis 6.2 起支持），必须为非负整数。

## 返回值

- 不带 `count` 时，返回头部元素的值；列表不存在或为空时返回 `nil`。
- 带 `count` 时，返回按头部到尾部顺序排列的元素数组；列表不存在时返回空数组。
- 对非列表类型的键执行会返回 `WRONGTYPE` 错误。

## 示例

```plaintext
# 准备示例列表，结果为 a b c d
RPUSH ba:l:job a b c d

# 弹出头部元素，返回 a
LPOP ba:l:job

# 剩余元素为 b c d
LRANGE ba:l:job 0 -1

# 一次弹出两个，返回 b 和 c
LPOP ba:l:job 2

# 弹出数量超过剩余数量时只返回现有元素
LPOP ba:l:job 10

# 列表已空时返回 nil
LPOP ba:l:job

# 键不存在时，不带 count 返回 nil，带 count 返回空数组
LPOP ba:l:job
LPOP ba:l:job 2

# 清理示例键
DEL ba:l:job
```

## 使用场景

- **队列消费**: `RPUSH` 入队、`LPOP` 出队，构成先进先出队列。
- **栈操作**: 与 `LPUSH` 搭配，实现后进先出。
- **批量取任务**: 使用 `count` 参数一次取走多个任务，减少命令往返。

## 注意事项

- 弹出元素后列表为空时，键会被自动删除；后续对它执行 `EXISTS` 会返回 0。
- 带 `count` 的 `LPOP` 与不带 `count` 的返回结构不同（数组对比单值），客户端代码要分别处理。
- 空列表场景下需要等待而不是立即返回 `nil` 时，应使用阻塞版本 `BLPOP`。
- 如果需要"从一边弹、压到另一个列表另一边"的原子操作，使用 `LMOVE`（旧命令 `RPOPLPUSH` 自 6.2 起建议替换为 `LMOVE`）。
- `LPOP` 与 `RPOP` 只影响元素个数，不改变剩余元素的相对顺序。

## 小结

`LPOP` 从列表头部弹出元素，配合 `RPUSH` 是最经典的队列组合；`count` 参数让批量消费变得简单。空列表返回 `nil`、空键返回空数组，这两个返回形态需要在客户端里显式区分。
