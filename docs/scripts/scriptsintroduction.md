# 脚本功能介绍

Redis 的脚本功能允许把一段程序发送到服务器端执行，在服务器内部一次性完成多条命令的操作。它主要解决两个问题：**多次网络往返带来的延迟**与**多步操作之间的并发一致性**。本章概述脚本功能的能力边界与适用场景，具体命令见后续小节。

## 1. 原子执行

脚本执行期间，Redis 不会插入处理其他客户端的命令，脚本内的多条命令对外表现为一个不可分割的操作：

- 并发客户端要么看到脚本执行前的状态，要么看到执行后的状态，不会看到中间状态。
- 这使得"检查再设置"（check-and-set）、"扣减再判断"这类多步逻辑可以不依赖分布式锁直接实现。

需要注意：脚本执行到一半出错时，已经执行的写命令**不会回滚**，因此脚本内部要先做参数校验再写入。

## 2. 减少网络往返

客户端逐条发送命令时，每条命令都有一次网络往返（RTT）。把逻辑放进脚本后，客户端只需一次往返：

```bash
EVAL "redis.call('INCRBY', KEYS[1], ARGV[1]) return redis.call('GET', KEYS[1])" 1 counter 5
```

返回 `5`。对于需要读取-计算-写回的业务（限流、库存扣减、排行榜更新），收益最为明显。

## 3. 服务器端计算

脚本可以在数据所在的地方做计算，避免把大批数据拉到客户端：

- 在服务器端遍历、过滤、聚合并只返回结果。
- 使用 `cjson`、`cmsgpack` 在服务器端直接处理 JSON/MessagePack 数据。

## 4. 两种脚本形态

| 形态 | 命令 | 特点 |
| --- | --- | --- |
| Lua 脚本 | `EVAL` / `EVALSHA` | 即发即执行，配合 `SCRIPT LOAD` 缓存脚本，按 SHA1 复用 |
| Functions（7.0+） | `FUNCTION LOAD` / `FCALL` | 以库为单位命名与管理，随复制与持久化同步，适合长期维护 |

两种形态使用同一个内嵌 Lua 引擎，语法与 API（`redis.call`、`KEYS`、`ARGV`）完全一致。

## 5. 使用限制

- **键必须显式声明**：脚本访问的所有键都要通过 `KEYS` 传入，这是集群路由与安全性的要求。
- **执行时限**：超过 `busy-reply-threshold`（默认 5000 毫秒）后，其他客户端会收到 `BUSY` 错误；需要人工 `SCRIPT KILL` 或重启处理，因此脚本必须简短。
- **无回滚**：脚本不是事务回滚语义，出错时已执行的写命令仍然生效。
- **沙箱环境**：Redis 内嵌 Lua 只开放 `string`、`table`、`math`、`cjson`、`cmsgpack`、`struct`、`bit` 等安全库，不能访问文件、网络与系统调用。

## 6. 典型应用场景

- **分布式锁的加锁/解锁**：用一段脚本完成"判断持有者-删除锁"的原子操作。
- **限流器**：结合 `INCR` 与 `EXPIRE` 实现固定窗口计数。
- **排行榜更新**：一次脚本内更新分数并返回新排名。
- **库存扣减**：读取库存、判断余量、扣减并记录，一步完成。

## 7. 小结

脚本功能把"多次命令往返"压缩成"一次脚本调用"，同时天然获得原子性。合理的使用方式是：脚本保持简短、键全部走 `KEYS`、常用脚本用 `EVALSHA` 或 Functions 管理。后续章节将分别讲解 `EVAL`、`EVALSHA`、`SCRIPT` 系列命令的细节。
