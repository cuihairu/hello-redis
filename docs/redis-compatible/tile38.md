# Tile38

Tile38 是一个开源的地理空间数据库、地理围栏（geofencing）和实时位置处理服务。它使用 Redis 协议通信，可以像使用 Redis 一样连接，但专注的是"位置数据"这一类问题：存储对象的经纬度、查询附近对象、以及当对象进入或离开指定区域时接收通知。

## 主要特点

- **原生空间索引**：内置多种空间索引（hash、quadkey 等），支持点、多边形等几何对象。
- **Redis 协议兼容**：使用 RESP 协议，redis-cli 与主流客户端可以直接连接。
- **地理围栏**：通过 `NEARBY`、`WITHIN`、`INTERSECTS` 等命令实现"进入/离开区域"的实时检测，支持 webhook、消息队列等钩子输出。
- **持久化**：支持 AOF 与快照。

## 快速上手

```bash
# Docker
docker run -p 9851:9851 tile38/tile38

# 使用 redis-cli 连接（Tile38 默认端口 9851）
redis-cli -p 9851

# 写入车辆位置（fleet 为集合名，truck1 为对象 ID）
127.0.0.1:9851> SET fleet truck1 POINT 33.5123 -112.2693
# 查询某坐标 500 米内的对象（返回对象 ID）
127.0.0.1:9851> NEARBY fleet LIMIT 5 POINTS POINT 33.462 -112.268 500
```

## 与 Redis GEO 的对比

| 维度 | Redis GEO | Tile38 |
| --- | --- | --- |
| 定位 | 通用内存数据库中的地理位置扩展 | 专用空间数据库 |
| 查询 | 半径、GeoHash 范围（点数据） | 半径、矩形、多边形，支持面与面相交 |
| 地理围栏 | 无（需轮询） | 原生支持，可推送通知 |
| 持久化与集群 | 继承 Redis | 自身 AOF/快照，单机为主 |

## 适用场景

- 车辆/骑手实时位置跟踪与调度；
- 电子围栏报警（进入禁区、离开服务区）；
- 附近的人、门店搜索等需要复杂空间查询的业务。

当业务只需要"半径内查询"时，Redis 的 GEO 命令足够；一旦涉及多边形围栏、面数据与围栏推送，Tile38 是更合适的选择。
